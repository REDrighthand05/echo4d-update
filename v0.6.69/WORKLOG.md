# WORKLOG — v0.6.69（带贴图网格的朝向检查分块算）

- 版本：v0.6.69（链 0.6.68 → 0.6.69）。本地热更新包，未发布，未推中转站，未碰桌面。
- 时间：2026-11-10 18:40–20:10（CST）。
- 改了什么：`app/echo_scene/voxel_export.py` + `app/installer/version.inc`（改号）。
  - `export_textured_mesh` 里判断 Poisson 曲面朝向的那一步，不再一次性算 `(顶点数, 视角数, 3)` 的整张 float64 表：改成每 5 万顶点一块算，攒每顶点的点积，最后取同一批值的中位数。每个顶点的算术一字未改，翻不翻的决定完全相同。
  - 没动：翻转体（列换位、法线取反、提示语）、`write_glb`（0.6.68 流式写码器）、`write_textured_glb`、贴图写码器其余部分、相机路线、批量导出；`voxels.py`、pipeline、fuse、depth_batch 全没动。
- 为什么：本轮量出来的真毛病。批量导出带贴图网格时，朝向检查在 638 帧任务上要一次性握 26.1 GB，直接抛 `_ArrayMemoryError` 死掉——本机装不下，桌面 24 GB 也装不下，长视频的带贴图导出根本跑不通。120 帧那次整段峰值 5,073 MB，朝向检查一只就占 3.2 GB。
- 实测（真任务，真代码）：
  - 120 帧：捕获峰值 5,073 → 1,779 MB；638 帧：从“跑不通”到 2,599 MB 跑完（3,693,148 三角、1,829,116 顶点、550/638 个视角）。分块没让 120 帧变慢（120.3 → 115.2 秒，噪声内持平）。
  - 新旧朝向检查逐值相同：在同一份数组上比，翻的决定 + 翻完的 tris/normals 字节全相同——真 120 帧网格、真 638 帧网格前 20 万顶点、合成翻/不翻/1 顶点/随机法线，6/6 一致。
  - 发版文件全流程活验（补丁后的文件直接跑产品原函数）：真 120 帧任务 ok True，1,115,028 顶点 / 2,262,962 三角，GLB 82,654,060 字节（`a1453cff…`），atlas PNG 与 lean 捕获逐字节相同，峰值 3,024 MB；trimesh 认这个 GLB（111 万顶点 / 226 万面）。
- 验过：`tests/test_v69.py` 69/69（基底血统 + 补丁复现 + 作用域 + 其余函数源码相同 + flip A/B 证据 + 捕获证据 + 发版文件全流程活验 + 边缘 + trimesh + 热更新模拟应用/中途回滚/中断回滚 + 写码器候选三条数钉住）；`verify_pack.py` 0 失败。包 513,204 B，sha256 `9b1c5492…a4b`。
- 没动：voxels.py（0.6.67 体素段原样）、pipeline.py、depth_batch.py、fuse.py、web_app.py、depth_video.py（冻结）、updater/hotupdate、web_ui。前端未动。深度未动（已量到顶）。
