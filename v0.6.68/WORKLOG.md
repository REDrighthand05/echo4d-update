# WORKLOG — v0.6.68（write_glb 流式写 BIN 块）

- 版本：v0.6.68（链 0.6.67 → 0.6.68）。本地热更新包，未发布，未推中转站，未碰桌面。
- 时间：2026-11-10 15:40–16:10（CST）。
- 改了什么：`app/echo_scene/voxel_export.py` + `app/installer/version.inc`（改号）。
  - `write_glb` 不再把三个 BIN 分块先 join 成一整块再写：三个分块的补齐长度直接用数组大小算出来（(nbytes + 3) & ~3，就是 `_pad4` 的结果），JSON 头（偏移、byteLength、total）在任何分块生成之前就已确定，三个分块逐个写盘、写完就丢。写出的字节与 JSON 和以前完全相同。
  - 没动：`write_glb` 的签名、JSON 结构、accessor、min/max、extras；`build_cube_mesh`、导出按钮、贴图写码器、相机路线、批量导出源码逐项相同；体素段（voxels.py）本身一个字节没动——它调用的写码器变了，调用方式没变。
- 为什么：先量后做（0.6.67 REPORT 留的候选：BIN 块先 join 再写，638 帧多握约 450 MB 临时量）。量出来比原话更大：旧写法在写盘那一刻同时握着三份分块 + 一份 join——120 帧约 664 MB、638 帧约 1,414 MB 的临时量，都坐在网格数组之外；新写法一次最多握一个分块（120 帧 181 MB、638 帧 386 MB）。
- 实测（真任务，真代码）：
  - 写 GLB 单独量（同网格 fork 子进程，两分支从同一份继承网格起步，两轮交替）：120 帧峰值 1,149.7/1,147.9 MB → 695.9/694.9 MB（省 453 MB，两轮稳定到 1 MB 内），写盘 12.08/2.40 秒（冷/暖）→ 1.77/2.07 秒；638 帧峰值 2,433.1/2,433.1 MB → 1,451.9/1,451.8 MB（省 981 MB），写盘 6.05/5.83 秒 → 3.77/3.65 秒。每任务四份文件逐字节相同（120 帧 sha `abd84ea4…`、638 帧 `c80e60f3…`，与 0.6.67 记的新分支哈希相同）。
  - 整段 `stage_voxel_model` 活验（发版文件）：120 帧峰值 1,220.3 → 787.8 MB、5.02 → 3.97 秒；638 帧峰值 2,517.4 → 1,535.9 MB、9.96 → 7.93 秒。PLY 与 0.6.63 基线逐字节相同（`1019ee63…` / `6c51bc53…`），GLB 与 A/B 新分支逐字节相同。
  - 导出按钮那条路（`export_colored_voxels`，真 120 帧任务）：voxel_color.glb `a50bc44d…` 两分支相同，PLY 与 info 也相同（info 的任务目录路径归一化后比）；峰值 406.5 → 406.7 MB——31 MB 的导出文件太小，省量落在噪声里，符合预期。
  - 合成小云旧 vs 新（空云、1 个三角面、5 点奇数补齐、1,000 点随机、非连续数组、int64 索引、float64 颜色、extras）：逐字节相同；独立解析器验过 JSON 块与 BIN 块（偏移、长度、计数、包围盒、载荷等于补齐后的数组）；trimesh 认新文件（1,000 顶点 / 2,000 面、带顶点色）。
