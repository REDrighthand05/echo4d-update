## 技术记录

- 用户报（2026-11-07 10:16，v0.6.41）：最小化没反应，最大化只对齐
  到左上角、画面没变大，关闭没反应。
- 查桌面日志 + 任务列表找到三个根因：
  1. 最大化其实改了窗口尺寸（日志 10:14:11、10:16:37：1282×998 →
     1920×1030 工作区，还原也正常），但页面没跟着重排，看着像
     “只挪到左上角”。现在最大化/还原之后推一把
     （SetWindowPos SWP_FRAMECHANGED），强制重算边框 + 布局，
     让页面跟着铺满。
  2. 最小化悄悄失败：win_minimize 只调了 pywebview 的 minimize()，
     在无边框窗口上什么也不干，try/except 还把错吞了、连日志都没有。
     现在直接调 Win32 ShowWindow(SW_MINIMIZE)，记日志，不行再回落
     到 pywebview 的 minimize()。
  3. 关闭卡住：日志 10:16:44 写了“已退出。”，但 PID 65592 还活着
     （内存 188 MB → 110 MB，窗口没了，进程卡住）。_quit 在调用线程
     里调 window.destroy()，destroy() 一直不返回，os._exit(0) 就
     没机会跑，关闭看着像没反应。现在 destroy() 放到守护线程里跑，
     永远卡不住退出；os._exit(0) 一定跑。
- 改动（只动 web_app.py + version.inc）：win_minimize 直接 ShowWindow
  + 日志 + 回落；_quit 守护线程 destroy + 无条件 os._exit(0)；
  win_toggle_max 最大化/还原后推一把重排；补 _SW_MINIMIZE = 6。
- 没动：v0.6.41 的 .NET 修（懒设最大化样式 + 防卫 MINMAXINFO）、
  resize 钩子、DWM 修饰、桥、深度、体素、更新器、web_ui。
